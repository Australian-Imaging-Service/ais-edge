CHECK IT IS WORKING

  FIRST, and after every upgrade:
    scripts/verify-live.sh <site>

  Helm having accepted these objects does not mean the pipeline runs. That
  script checks readiness rather than pod phase, reaches XNAT from inside the
  upload pod with the site's own credentials, and confirms the alert rules
  actually loaded. Its exit code is the number of failures.

  It does not perform a modality-to-receiver C-STORE check for DICOM port
  {{ .Values.orthanc.dicomPort }}. SKIP means that network leg remains unverified;
  hostPort is not inherently unreachable from every cluster network. Prove it
  with a real C-STORE, below.

NOT REMOVED BY `helm uninstall`
  The namespace, the PersistentVolumes and their claims carry
  helm.sh/resource-policy: keep and Retain. The chart-managed pipeline storage and externally managed Secrets are
  retained, but this is not a backup or a promise that previously reclaimed
  studies remain. Subchart PVC retention has its own configuration. Removing data is a
  separate deliberate act.

  with another name cannot take it over: set storage.storageClass.create: false,
  or delete it (kubectl delete storageclass {{ .Values.storage.storageClass.name }})
  when no PersistentVolume uses it.

{{- if and .Values.observability.enabled (not .Values.observability.stack.alerting.emailTo) }}

  ⚠  NO ALERT CAN BE DELIVERED FROM THIS SITE
    observability.stack.alerting.emailTo is empty. With both observability
    switches enabled, validation rejects this configuration before deployment.
    With the stack disabled there is no local Alertmanager to deliver mail.
    Shipper-only operation does not itself provide a notification receiver.

    Filling in the alertmanager-smtp Secret is NOT enough on its own. That is
    the credential for talking to the relay. These four say who gets the mail
    and which relay to use, and they live in the site values file:

      observability:
        stack:
          alerting:
            emailTo: imaging-ops@example.org
            emailFrom: ""          # defaults to emailTo
            smtpHost: smtp.example.org
            smtpUsername: ""       # must match `username` in alertmanager-smtp

    If this site deliberately uses shipper-only observability, configure and
    test its external evaluator and receiver. A local enabled stack requires
    the mail facts above; an empty inbox does not demonstrate health.
